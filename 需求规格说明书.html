引言

1.1 编写目的

本文档面向“互联网资产和信息系统管理”业务场景，系统性地定义平台的业务范围、功能需求、数据需求、非功能需求与界面交互要求，作为产品设计、UI 原型制作、研发实现、测试验收与上线评估的共同依据。

预期读者包括：业务主管部门（需求提出方与验收方）、产品与交互设计人员、前端与后端研发人员、测试人员、安全与审计人员、运维实施人员。

1.2 项目背景与建设目标

当前互联网资产与信息系统分散在各归属单位、以 Excel 台账和人工报送方式维护，存在登记口径不统一、重复登记、责任人不明确、状态更新滞后、停用报废资产长期“挂在账上”、统计口径难以支撑上级核查与安全审计等问题。

本平台的建设目标是建立“一本账”式的资产治理底座，实现三个层次的闭环：

  • 登记标准化——统一的登记入口与按类型分列的字段模板，配套佐证材料上传与自动查重，源头保证数据真实、合规、不冗余；
  • 维护全周期——覆盖启用、变更、停用、报废、责任人交接的全生命周期，每一次变更自动留痕，责任始终可追溯，杜绝“僵尸资产”；
  • 查询多维化——支持按类型、单位、状态、时间、责任人等维度组合统计，输出可视化图表与可导出的标准报表，支撑管理层决策与外部核查。

1.3 术语与缩略语

术语 / 缩略语说明
互联网资产本单位拥有或使用的、暴露于互联网或与互联网存在连接关系的资产实体，包括域名、IP 地址、应用系统、服务器、终端设备等五类。
资产台账以归属单位为主键组织的资产明细集合，是登记、维护、统计的统一数据源。
核心字段某一资产类型下必须登记的关键信息项，如域名备案号、IP 网段、系统名称、部署位置、上线时间、归属部门、负责人及联系方式。
佐证材料证明资产真实性与合规性的附件，如域名备案证明、IP 分配文件、系统上线审批表、设备采购合同等。
唯一性校验提交登记时对 IP 地址、域名、MAC 地址等资产标识进行全量比对，发现重复即拦截并提示的处理机制。
隔离管理对停用、报废资产进行的逻辑隔离：退出在用统计口径，但历史信息、材料与变更轨迹完整保留。
僵尸资产实际已下线或不再使用，但台账中仍标记为在用、且长期无人核对的资产记录。
CMDB配置管理数据库（Configuration Management Database），本平台的上游配置数据来源之一。
SRS软件需求规格说明书（Software Requirements Specification）。

参考文件：《网络安全法》《数据安全法》《信息安全技术 网络安全等级保护基本要求》（GB/T 22239）、《软件文档管理指南》（GB/T 8567）、《信息系统安全管理要求》及本单位《互联网资产管理办法（试行）》。

总体描述

2.1 产品定位与系统边界

本平台为内部管理类 Web 应用，定位为“互联网资产与信息系统的唯一权威台账”。系统边界内包含：资产登记、资产台账、更新维护、统计报表四个业务域；系统边界外但需对接的包括统一身份认证（SSO）、短信/站内信通知服务、CMDB 与备案信息核验服务。

边界说明 资产的实际监控探活、漏洞扫描、流量分析等能力不在本期范围，平台仅通过接口接收其“运行状态”与“在线情况”作为核对参考。

2.2 用户角色与权限矩阵

角色职责定位主要权限
资产责任人资产的直接使用与管理者登记本人负责的资产；修改资产基本信息；更新运行状态；上传/补充佐证材料；响应定期核对提醒；发起责任人变更申请。
单位资产管理员本单位台账的汇总与审核者审核本单位登记申请；查看与导出本单位资产清单；批量修改与批量状态更新；指派责任人；催办核对。
平台管理员全局数据与规则维护者全量资产查看与导出；字典与字段模板配置；查重规则配置；跨单位数据调拨；操作日志审计。
决策 / 审计用户管理层与内外部审计人员只读访问统计报表与可视化看板；导出全量统计报表；查看变更历史（不可编辑）。

3.2 资产登记上传

3.2.1 功能描述

提供互联网资产标准化登记入口。各单位可按资产类型分别登记信息，填写对应核心字段，上传与类型匹配的佐证材料；系统在提交时自动进行唯一性校验，校验通过后写入台账，并生成以归属单位为单位的资产台账视图。

3.2.2 业务流程

选择资产类型 → 填写核心字段（实时查重） → 上传佐证材料 → 提交校验 → 入库并生成台账 → 通知单位资产管理员复核。

3.2.3 功能点说明

编号功能点需求描述与验收要点
FR-01类型化登记入口提供域名、IP 地址、应用系统、服务器、终端设备五类资产的独立登记入口；切换类型时表单字段、必填规则与材料要求同步切换，不得要求用户手动记忆字段差异。
FR-02核心字段采集按类型呈现核心字段（详见表 3-2）；支持分组展示“登记信息 / 责任与管理 / 时间与位置”，必填项以红色星号标识，缺失时不放行提交。
FR-03类型专属字段域名须采集备案号与解析 IP；IP 须采集网段与分配方式；应用系统须采集访问地址与等保级别；服务器须采集操作系统与资产编号；终端须采集 MAC 与使用人。
FR-04实时唯一性校验用户输入标识（IP / 域名 / MAC / 访问地址）后即时比对全量台账；命中重复时在字段下方红色提示，展示已登记资产名称、归属单位与状态，并阻止提交。
FR-05唯一性提示口径提示文案须包含“重复对象 + 归属单位 + 当前状态 + 建议动作”，避免用户仅看到“已存在”而无从处置；支持一键跳转查看该资产详情。
FR-06佐证材料上传支持点击与拖拽上传，允许 PDF / JPG / PNG / ZIP，单文件 ≤ 20MB，单资产 ≤ 10 个附件；上传后可在表单内删除、查看文件名与大小。
FR-07材料与类型绑定系统依据资产类型推荐材料名称（域名备案证明、IP 分配文件、系统上线审批表、设备采购合同）；未上传任何材料时给出显式拦截提示。
FR-08台账生成与分类展示提交成功后自动生成单位资产台账记录，支持按资产类型分类切换查看，便于快速核对；新记录默认状态为“启用”，并标记“待复核”。

3.2.5 唯一性校验规则

校验对象校验时机比对范围冲突处理

3.2.6 界面与交互要求

  • 采用四步引导（选择类型 → 填写字段 → 上传材料 → 提交入库），步骤条实时反映完成进度；
  • 右侧固定「唯一性校核」状态面板，实时呈现三项校验结果（通过 / 冲突 / 待输入），让用户随时掌握可否提交；
  • 必填校验失败时，浏览器焦点定位到第一个错误字段并平滑滚动，同时以 Toast 汇总错误数量；
  • 提交成功后给出明确回执（资产编号 + 台账位置），并自动跳转资产台账，避免用户重复提交。

异常场景：①网络中断时保留本地草稿，恢复后提示继续填写；②附件超过大小限制时明确提示上限与当前大小；③并发提交同一标识时以后提交者为准并回滚前者，提示“该资产已被他人登记”。

3.3 资产更新维护

3.3.1 功能描述

支持资产信息的全生命周期维护。资产责任人可随时修改资产基本信息、更新资产运行状态（启用 / 停用 / 报废），系统自动记录每一次变更的内容、时间、变更人与变更原因，形成可追溯的变更历史日志。提供批量操作能力，并对停用、报废资产自动隔离管理；支持责任人变更申请与定期核对提醒，确保责任明确、账实相符。

3.3.2 状态流转规则

当前状态允许流转必填信息系统行为
启用停用、报废变更原因（≥10 字）记录变更日志；转入隔离管理时同步退出在用统计口径。
停用启用、报废变更原因、恢复说明（启用时）恢复启用时须重新确认责任人与部署位置；日志标注“恢复启用”。
报废启用（需审批）变更原因、审批单号默认长期隔离；恢复启用需单位管理员审批，防止误操作。

3.3.3 功能点说明

编号功能点需求描述与验收要点
FR-09基本信息修改责任人可修改除资产标识外的全部字段；修改资产标识须走变更审批，防止绕过唯一性校验。
FR-10状态更新提供启用 / 停用 / 报废三种状态切换，弹窗内以卡片式单选呈现各状态含义，必须填写变更原因方可提交。
FR-11状态可视化台账、详情、看板中统一使用状态色标（启用-绿、停用-琥珀、报废-灰），并辅以文字，避免仅靠颜色传达信息。

FR-13变更历史查询支持按资产、变更类型、时间范围、操作人检索；在资产详情中以时间线形式展示完整生命周期轨迹。
FR-14批量修改勾选多项资产后可统一修改归属单位、归属部门、责任人、部署位置等字段；执行前须展示影响条数并强制填写原因。
FR-15批量状态更新支持对同类资产批量变更运行状态，逐条生成日志（归并为一次批量操作记录，可下钻到单条）。
FR-16停用报废隔离停用、报废资产自动标记并进入“停用与报废”隔离视图，保留全部历史信息与佐证材料，可查看、可恢复，不参与在用资产统计。
FR-17责任与核对支持责任人变更申请（原责任人 → 新责任人，需接收确认）；系统按季度向责任人推送核对提醒，超期未核对在台账与看板双重标记“待核对”。
